# v5 静态审查记录 — 2026-11-17

范围：训练入口、分阶段配置、模型与损失、几何监督、数据与增强、DINO缓存、checkpoint与两个demo。仅阅读源码、对照Lightning 2.2.5生命周期及官方教师结构、解析语法/YML、读取本地数据文件列表/PNG头/H文本。没有导入或执行项目，没有安装依赖、加载模型、前向/反向、训练、推理或测试。

## 已定位并修复

| 问题 | 后果 | 修复位置与做法 |
|---|---|---|
| FP16相似度填入`-1e9` | `16-mixed`粗匹配掩码可能溢出报错 | `coarse_matching.py`中掩码和softmax使用FP32 |
| RoPE的FP16缓冲与BF16输入混用 | q/k被提升为FP32，和v类型不一致，SDPA无法计算 | `position_encoding.py`按输入类型取sin/cos |
| 半精度大坐标叠加亚像素偏移 | 小偏移被舍入，影响定位精度 | `fine_matching.py`坐标计算使用FP32 |
| demo将FP16坐标传给OpenCV | `findHomography`输入类型不支持 | 两demo使用FP32缩放和点坐标 |
| 空GT日志引用不存在的`pair_names` | 无有效对应时先触发KeyError | 记录数据集已提供的`pair_id` |
| 反向GT使用图0网格长度 | 两幅图尺寸不同时索引错配 | 使用图1的网格长度 |
| 补边坐标置零后又经H变换落入有效区 | 无效区域成为GT正样本，污染细匹配采样 | 生成GT矩阵后显式排除双方padding |
| 细匹配窗口越界坐标填零，warp越界索引也压为零 | 虚构位置可能通过双向回查，产生伪GT | 对展开窗口的源/目标有效位置和双向warp窗内条件联合筛选 |
| 通用增强函数对非空method主动抛出NotImplementedError，且数据集没用该参数 | 非默认配置不可用，配置与实际数据流不一致 | 移除失效入口，保留两阶段已有增强 |
| 风格生成器自行选择CUDA | CPU训练或多卡时可能跑错设备 | 由Trainer的root_device指定 |
| 余弦增强常量图归一化分母为零 | 产生无效像素 | 为零对比度的分母保留数值下限 |
| Pillow10已移除`Image.ANTIALIAS` | 指定style图缩放时失败 | 改用`Image.Resampling.LANCZOS` |
| 每张增强图后清空CUDA allocator缓存 | 引入重复分配和潜在同步开销 | 去掉逐图`empty_cache()` |
| 细监督用Python循环逐个窗口做反查 | 每batch数千次小张量操作 | 用数学等价的`gather`一次索引 |
| loss_scalars每步四次转CPU，但训练日志已直接读GPU损失 | 无用的设备拷贝与同步 | 保留detached字典接口，去掉CPU拷贝 |
| 训练参数散落、固定目录重复启动可能覆盖 | 不便分别实验与追溯 | 阶段YML、独立init/resume路径、run目录、编号归档 |

同时移除了全局warnings屏蔽与失效训练配置字段；没有加入自动下载、自动试跑、自动回退骨干或额外增强框架。

## 数据与接口核对

- 本地BIT ±30°数据：803个样本目录，每目录21个文件；按原规则跳过第一个目标配对，得到7227对，引用8030张不同图片。该规则未改变。
- 引用的PNG头部尺寸均为512×512；图像和同名H文本的顺序未发现错位。
- 8030个H文本均有9个有限数且可逆，最小绝对行列式约0.5487。这是文本数值核查，不证明图像内容和H标注必然正确。
- 学生输出`128×256² / 196×128² / 256×64²`，与DGIM的FPN、粗匹配及5×5细匹配接口一致；亚像素MLP和教师投影的梯度在源码上连通。
- 教师仍为冻结DINOv3 ConvNeXt-Large第二stage，384通道、stride8；原生格点中心与学生格点的3.5像素偏移通过固定采样对齐。缓存绑定像素、有效区域和预处理规格。
- 两个训练命令各只调用一次当前阶段的`fit`，无跨阶段自动串联。微调只初始化匹配器；resume恢复同阶段优化器、scheduler和loop。
- 保存回调顺序根据PL 2.2.5源码核对：模块记录epoch日志，EarlyStopping设置停训状态，Checkpoint随后保存。每N轮及末轮/早停轮保存，`last.ckpt`只在保存事件更新。
- 从首次历史归档恢复时，该文件可能尚未记录`last_model_path`；恢复回调明确绑定当前目录的`last.ckpt`，避免原生版本计数将最新副本改写成`last-v1.ckpt`。历史归档依然保留版本计数保护。
- epoch边界恢复后首个DataLoader依据恢复进度设置教师开关；第11轮及以后不读教师缓存。调度器用实际优化步数计算warmup，梯度累积不会多推进学习率。

## 性能潜力与未验证范围

定制RepViT保持原DGIM的`1/2、1/4、1/8`接口，降低了骨干的估算计算量，并保留RepViT的深度卷积、通道混合与SE设计。训练期教师可提供额外表征约束，停止教师后又允许学生继续适应匹配损失；这些是可能改善结果的理由，不是已测得的收益。

本模型是从头训练的定制结构，不能将官方M2.3的分类指标当成本模型的匹配指标。DINO预训练域与跨模态任务可能不同，0.05的辅助权重尚未调优；更深的学生也可能更难优化。保留相同后端只降低了接口变更风险，不保证精度上升。骨干GMAC减少也不等于整网延迟同比下降，注意力、FPN窗口展开及磁盘缓存读取仍有开销。

本轮不能证明的内容：实际依赖安装兼容、官方checkpoint加载、融合数值等价、运行峰值显存、训练收敛、吞吐与测试集准确率。默认尺寸512处于现有RoPE表支持范围；输入长边超过2048需要另行扩展位置表。原冻结风格网络的历史残差调用行为未改动，以保持与已有权重配套。

判断是否超过DGIM，应在相同数据划分、训练预算和评测协议下比较三组：RepVGG无教师、定制RepViT无教师、定制RepViT加教师，并重复种子。仓库保留这些训练入口；没有把训练loss早停或demo可视化当作论文定量评测。
